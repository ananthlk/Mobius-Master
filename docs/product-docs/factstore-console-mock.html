Normalisation, done visibly at write: 90 days — 90 calendar days = 90 days. The verbatim value stays "90" / "calendar days". A store that holds only the normalised number cannot be audited, and a wrong conversion in a deadlines domain is unrecoverable.

What this screen is for

The evidence is one click from the value, not in a log. Every row opens to its quote, its document, its page, and which of the six checks it passed. An operator deciding whether to accept a fact should not have to trust a summary — the reason is right there.
Three rows cannot be written, and the screen says so rather than hiding it. They cite “Provider Dispute Form”, which chat named in its reasoning log but never returned in sources — so it has a name and no id. A name cannot be joined back to the corpus, and that is how a store ends up with facts it cannot trace.
“Not checkable” is a third state, deliberately. calendar days and the anchor event carry no code or number to look for, so the in-source check has nothing to test. That is not a pass and not a failure. Collapsing it into either would either certify something unverified or discard something good.
Prototype, not build. The rows, quotes, pages and check results are real output from the Sunshine Health run. The staging animation is theatre — the real run takes minutes and would arrive by poll.
