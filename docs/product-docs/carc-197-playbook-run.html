What happened, and why it is the result I wanted

Chat proposed three grounds and cited zero documents. auth_obtained_not_linked, emergency_urgent_care_auth_exemption, retroactive_auth_provider_error. It searched, found nothing usable, and answered anyway — from model knowledge, fluently, at 1,391 characters.
The grounds are substantively right, and every one was refused. They match the branch set I drew by hand yesterday almost exactly. The Judge refused all three at gate 2: document_not_cited — “(none)” is not among the documents the answer cited. Being correct is not the bar. Being sourced is.
Which indicts my own drawing. The five branches in the CARC 197 schematic came from the same place chat’s came from — plausible domain knowledge, no citation. Had I fed that drawing in as a playbook, the machine would have executed against real claims on a branch set with no rulebook behind it. The refusal applies to me.
The Arbiter wrote no playbook and filed an acquisition. not_in_corpus → acquire. That is the honest state: we do not hold a document describing the grounds for disputing a CARC 197 under Florida Medicaid, and until we do, the denial loop has nothing legitimate to run on.
It also crashed, and the crash was mine. The acquire path assumed a manifest URL and threw KeyError: 'url' after the chat call had already been spent. An acquire with no known target is still an acquire — the loop knows a source is missing and does not know which one. Guarded.
