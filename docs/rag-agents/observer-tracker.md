## Post-signoff fix #1 (2026-07-24): quote-less LLM citations were silently reading as verified

Tech Review flagged a small hygiene issue while reviewing Synthesis — `_LLM_UNVERIFIED_REASON = "llm_partial_match"` hand-copied in three places (filler_c.py's inline literal, observer.py, synthesis.py). Investigating it surfaced something bigger: filler_c.py gives a quote-LESS citation (LLM cited a doc/page but no verbatim quote — nothing to falsify) the SAME `assignment_reason="llm_retrieved"` as a genuinely quote-verified one. The real distinguishing signal is `FilledChunk.quote_verified` (`True`/`False`/`None`) — a field Eval already ruled must drive Synthesis's `verified` flag (`synthesis.py:588`, `quote_verified is True`). Observer's `_evaluate_llm_retrieval` never received that same fix: it checked `assignment_reason == "llm_partial_match"` alone, so a quote-less citation silently counted as sufficient (`SATISFIED`) when nothing had actually been confirmed — it should have triggered `WOULD_BENEFIT`. Same overstating-confidence failure class Eval already caught once, just not caught in this module too.

**Fixed:** `ASSIGNMENT_REASON_LLM_RETRIEVED`/`_RETRIEVED_EXTERNAL`/`_PARTIAL_MATCH` promoted to `fillers/contracts.py` (closes Tech Review's dedup ask — filler_c.py/observer.py/synthesis.py all import from there now, zero hand-copies). `observer.py`'s sufficiency check now reads `chunk.quote_verified is not True`, scoped to LLM-citation `assignment_reason`s only — matching synthesis.py's already-correct logic exactly, one definition of "verified," not two. A stale comment on `synthesis_contracts.py`'s `verified` field (still describing the old assignment_reason-only rule) corrected too. 2 new regression tests (quote-less-citation-not-verified; non-LLM chunk never swept into the unverified count), 25/25 `test_observer.py` (at the time), 521 passed/2 skipped full retriever+router suite, no regressions. Independently re-verified by Synthesis against their own file (constants real, `verified` derivation semantics byte-for-byte unchanged, full suite matching exactly).

Consequence caught and handled: Eval's committed calibration run was executing when this landed (n_run=2/22) — Python's in-process module cache meant an already-running harness process would keep executing pre-fix logic regardless of the file change. Retriever killed and restarted the run once flagged. See `feedback_midrun_fix_stale_import_risk` memory for the general lesson.

**Retriever's ruling on scope:** does not reopen formal sign-off — the architectural/contract/control-flow properties Chat/DB/TECH each verified (pure function, no DB writes, same enum/reason shape) are untouched; this is a correctness fix moving toward more accurate verdicts, not a scope change. Retriever sent Chat/DB/TECH a transparency FYI directly rather than requiring a full re-review.

## Post-signoff fix #2 (2026-07-24): Filler s's hit was wrongly satisfying its whole slot — two rounds

**Round 1 (Retriever):** re-instrumenting the calibration harness after a Router payload fix put `['s','a','b']` in the ladder for content queries, live evidence showed the continuation loop stopping after `s` alone, every time, even though `a`/`b` were planned and would have retrieved real, relevant policy content. Traced to `_evaluate_fact_store`'s bar (`occupancy > 0` → `SATISFIED`) resting on the docstring's claim "a fact-store slot has capacity 1, one verified fact answers it fully." **Verified directly against `shape/slots.py` (not taken on Retriever's word alone):** no dedicated capacity-1 fact-store slot type exists anywhere in the chain — for PRECISE posture, the single `direct_answer` slot gets `capacity=breadth` (e.g. 10), and filler_s fires on that SAME shared slot as a/b/c/d, always assigning at most one chunk. Live evidence (cmhc001): the fact-store hit was the bare string `"68069"`, and the resulting s-only answer scored 0.00 on the judge rubric. First fix made the bar capacity-aware (`not under_filled` → `SATISFIED`, matching a/b/d).

**Round 2 (Eval, same day):** capacity-aware still wasn't the right *criterion*, even though it was behaviorally correct today. It makes `capacity == 1` a proxy for "s owns a dedicated fact slot" — but no such slot type exists anywhere in the `AnswerSlot` contract, and **verified this is genuinely unreachable, not just unlikely**: `shape/structure.py`'s breadth formula has a real minimum of 7 across every defined `caller_mode` (`chat.copilot`: `round(10*0.70/0.95)=7`) — capacity can never legitimately be 1 today. Eval's sharper rule doesn't depend on that formula never changing: since s can never see anything but a shared content slot in the current data model, it should NEVER independently emit `SATISFIED`, full stop — consistent with Router's own already-shipped planning-time rule ("s may never be the SOLE rung of a required content slot — s supplements, never substitutes"), applied at execution time too, not a new principle.

Also checked, per Eval's ask, whether the same "s over-trusted as a standalone answer" pattern reaches `contract.py`'s `_pick_chosen_slot` (a possible 4th manifestation, after seed priors/accuracy_estimate/this) — it selects at the SLOT level from Synthesis's already-merged citations, not a single chunk, so once this fix lets a/b/c/d actually run, the slot contains real content before Contract ever sees it. No separate bug found there.

**Fixed (final):** `_evaluate_fact_store` now ALWAYS returns `WOULD_BENEFIT`/`EXHAUSTED_ATTEMPTS` — never `SATISFIED` — regardless of hit or miss; a hit is real, certified, supplementary evidence, never a sole answer. Simpler than round 1's capacity check and doesn't rely on an accidental invariant. 3 regression tests (capacity=1 hit still not satisfied alone; capacity=10 hit not satisfied; exhausted once attempts used up), 27/27 `test_observer.py`. Full suite confirmed clean including live integration tests: **540 passed, 2 skipped** (`test_integration_production_shapes.py`'s real-Vertex-AI-call suite, ~17min runtime, includes `test_real_content_query_does_not_collapse_to_single_strategy` — directly exercising the exact failure mode just fixed).

**Scope:** correctness-only, same as fix #1 — Retriever's call on whether Chat/DB/TECH need another FYI.

**Revisit trigger, documented not just discussed (Eval's forward note):** "s never satisfies" is only correct because no dedicated fact-slot TYPE exists in the `AnswerSlot` contract today. If one is ever added (a slot where a single certified fact genuinely IS the authoritative answer), this rule becomes wrong — the fix at that point is keying `SATISFIED` off slot-type (fact slot → s satisfies; shared content slot → s supplements), not another proxy. Written directly into `_evaluate_fact_store`'s docstring so it's a known, findable revisit condition rather than a silent-wrong when the data model grows.

**Five bugs across three layers, now closed (Eval's frame):** seed priors making s Pareto-dominant at planning time (Router fixed via supplement gate), `accuracy_estimate` reading as P(answered) not P(fact-correct) (Eval's seed-file comment), and this — Observer's SATISFIED-on-hit at execution time — are one root category error (s over-trusted as a general answer strategy) manifesting at three layers. `contract.py`'s `_pick_chosen_slot` checked as a possible fourth layer and cleared (operates on Synthesis's already-merged slot citations, not a single chunk).

## Scope and lineage correction (2026-07-24)

This module went through two real design generations — a mechanical bool+float+bool verdict (v1, `ObserverVerdict{satisfied, confidence_score, speed_budget_exceeded}`), then a Bayesian confidence-posterior addendum (`observer-bayesian-confidence-spec.md`, never built) — before landing on what's actually shipped: a discrete per-strategy `evaluate(strategy_id, filled_slot, ...) -> (verdict, reason)` using Router's own `WOULD_BENEFIT`/`SATISFIED`/`EXHAUSTED_ATTEMPTS` enum, no shared confidence scale across strategies. Neither earlier generation was marked superseded in writing until 2026-07-24, when Observer went looking for a spec to route alongside sign-off and found three contradictory drafts. `observer-module-spec.md` was rewritten to v2 to describe reality; the Bayesian addendum and the original change request both now carry supersession banners pointing to v2. This tracker and v2 document the corrected/actual scope only.
