**Why this spec exists, and the correction it documents:** Synthesis's original kickoff message (from Retriever, 2026-07-24) framed this module as authoring the final answer — "text + citations — that Chat actually shows the user." **Ananth corrected this directly, same day, before any code was written against that framing:** Synthesis does NOT author answer text. ---

## 1. Where Synthesis sits in the pipeline

```
Shape → Pool → Router → Fillers → Observer → **Synthesis** → Contract → Timing
```

Synthesis is a pure post-processing/compilation step. It does not call Fillers, Pool, Router, or any retrieval strategy. It reads what Fillers produced (`FilledShape`, per-slot `FilledChunk`s) and what Observer verdicted (per-slot `SATISFIED`/`WOULD_BENEFIT`/`EXHAUSTED_ATTEMPTS`/`EXHAUSTED_BUDGET` + reason), and produces one compiled `SynthesisResult`. It has one DB dependency of its own (unlike Fillers a/b, which are pure-over-the-pool): document-name resolution and neighbor completion both need a real `AsyncSession`, same as fillers c/d/s already do.

## 2. Input — what Synthesis receives

- `FilledShape` (Step 3, `fillers/contracts.py`) — per-slot `FilledChunk`s: `text`, `source_type` (internal/external), `document_id`/`url` (mutually exclusive), `document_status` (planned/live), `assignment_reason`, `original_score`, `is_neighbor`.
- `verdicts: dict[str, SlotVerdict]` (optional) — per-slot verdict from Observer's `evaluate()` + Router's ride-along stamping. Optional because Observer isn't wired into `orchestrator.py` yet; absent slots get an empty `SlotVerdict()` rather than a fabricated one.
- `filler_emit_by_slot: dict[str, dict]` (optional) — per-slot LLM-call attribution (`model_used`/`llm_call_id`) from whichever rung filled that slot (today only filler_c produces this). Optional because today's `orchestrator._run_fillers_simple` discards each rung's `emit` dict once it extracts the `FilledSlot` — nothing reaches here yet, but the parameter exists so wiring it through later needs no signature change.
- `db: AsyncSession` — for document-name resolution and neighbor completion.

## 3. Output — what Synthesis produces

```python
@dataclass
class CompiledCitation:
    index: int                    # 1-based, stable — Chat/its LLM cite by this
    chunk_id: str
    document_name: str             # resolved here — never present upstream
    text: str
    source_type: str                # "internal" | "external"
    document_id: str | None
    url: str | None
    page_number: int | None
    paragraph_index: int | None
    content_sha: str | None
    document_status: str | None     # "planned" | "live" | None — must survive, never dropped
    authority: str | None            # "authoritative" | "external" | "planned" | None — feeds Chat's grounding badge
    verified: bool                  # False iff filler c's cited quote did not verify (assignment_reason == "llm_partial_match")
    is_neighbor: bool
    original_score: float | None
    slot_id: str
    slot_semantics: str

@dataclass
class CompiledSlot:
    slot_id: str
    slot_semantics: str
    capacity: int
    required: bool
    citations: list[CompiledCitation]
    occupancy: int
    under_filled: bool
    verdict: str                    # passed through verbatim, never normalized
    verdict_reason: str
    ride_along: bool
    model_trace: dict                # {stage, model_used, llm_call_id} when the caller supplies it

@dataclass
class SynthesisResult:
    query: str
    slots: list[CompiledSlot]        # Chat authors per-slot, using verdict to calibrate confidence language
    citations: list[CompiledCitation] # flat, globally-indexed, cross-slot-deduped — maps directly onto Chat's SourceRef
    telemetry: SynthesisTelemetry     # diagnostics-only counts, see §6
    coverage_diagnostics: dict[str, CoverageDiagnostic]  # blend model, 2026-07-24 — one per slot, including empty ones; Router's decide_continuation() consumes this on the next loop iteration, see §4 step 1
```

`SynthesisTelemetry` also gained two blend-model counters (2026-07-24): `fusion_dropped_redundant` (MMR rejected as truly redundant) and `fusion_dropped_budget` (never evaluated — that slot's sub-budget ran out first) — distinct from the pre-existing `citations_trimmed_for_budget`, which is a later, separate global safety-net trim after neighbor completion. Both feed the reconciliation guard: `chunks_out == chunks_in - fusion_dropped_redundant - fusion_dropped_budget - duplicates_removed + neighbors_added`.

`CompiledCitation` field names line up with Chat's `SourceRef` (`mobius-chat/app/skills/registry.py:60`) field-for-field — `document_name`/`source_type`/`url`/`document_id`/`page_number` need no translation layer.

## 4. What Synthesis actually does

1. **Per-slot cross-strategy fusion — superseded 2026-07-24 by the blend model (Ananth's direct framing, relayed via Retriever): "the Synthesizer is the one to rerank across strategies and start another fill so that we honor the token limits."** Retention (upstream, orchestrator-owned) now unions every executed rung's `FilledChunk`s into a slot rather than discarding superseded rungs, so a slot's `chunks` can hold candidates from several strategies (a/b/c/d/s) at once. Per slot: group by strategy (derived from `assignment_reason`, the only reliable signal retention itself carries), rank within each group (the original score-first ordering below, now applied per-group not globally), fuse across groups with Reciprocal Rank Fusion (`fusion.py:rrf_fuse`, rank-based specifically because raw scores aren't comparable across strategies — see the now-superseded single-strategy note this replaces), then select to a per-slot token sub-budget with Maximal Marginal Relevance (`fusion.py:mmr_select`, TF-IDF cosine similarity, λ=0.7 relevance-leaning, 0.85 redundancy threshold) — a real blended fill ("3 from a, 2 from b"), not winner-takes-all. Per-slot sub-budget derived from Router's `per_slot_payload_tokens` as split weights (not the budget itself — a distinct, generally smaller, Chat-sourced quantity), falling back to effectively unbounded when not supplied. Emits one `CoverageDiagnostic` per slot (including empty ones) for Router's `decide_continuation()` to consume on the next loop iteration. Still does not rerank across slots: slots remain semantically distinct buckets (`direct_answer`/`thematic_exploration`/`external_context`).
2. **Neighbor completion** — for internal (`document_id`-bearing) chunks that don't already have a neighbor sibling present in their slot, calls `corpus_search._expand_with_neighbors` (the same helper Pool's own neighbor step uses — reuse, not reinvention). External/fact-store chunks have no page/paragraph anchor to expand from; skipped, counted in telemetry, never silently dropped.
3. **Cross-slot dedup** — `chunk_id` first, then body-text and `content_sha` checked **independently** (a match on either counts as a duplicate — neither is a fallback gated behind the other's absence). Originally mirrored `pool/dedup.py`'s content_sha-primary/body-text-fallback ordering; **corrected 2026-07-24 per Eval's finding**: `content_sha` is salted per-document in this schema, not a pure content hash (Router's diversity-signal work found 5 byte-identical-text chunks with 5 distinct `content_sha` values; Filler b's tracker documented the same for 15 rows) — so the same fact/boilerplate duplicated across two different documents has identical text but different `content_sha`, and the original ordering let it survive dedup. Body-text is now always checked regardless of whether `content_sha` is present. That module only dedupes within one pool build; a chunk can still land in two different slots, or reappear across filler retries, by the time Fillers are done — this catches that.
4. **Document-name resolution** — a real, confirmed gap: neither `PoolCandidate` (`pool/contracts.py`) nor `FilledChunk` (`fillers/contracts.py`) carries a document display name anywhere in the pipeline. Resolved via a batched lookup against `rag_published_embeddings` (`document_display_name`/`document_filename` — the same columns `corpus_search.py`'s neighbor-fetch already reads). Fallback chain: (a) internal chunk, lookup hit → real name; (b) internal chunk, lookup miss → short id label **and a logged warning** (an ops/data-integrity signal — that chunk's `document_id` should have a documents-table row; Chat's ask, 2026-07-24, not to silently paper over it); (c) external (url) chunk → humanized last URL path segment (`/providers/prior-authorization-requirements` → "Prior Authorization Requirements" — Chat's rendering convention, readable and honest, no false precision), falling back to domain if the path is empty.
5. **Citation building** — `verified` flag from filler c's `assignment_reason == "llm_partial_match"`; `document_status` passthrough unchanged (Product-Awareness's reality gate — never cite a "planned" doc as live, required field with no default per PA's sign-off condition); `authority` inferred from `source_type`/`document_status` (Chat's sign-off gap, 2026-07-24 — feeds the grounding badge, which computes "grounded" only when every cited source is authoritative; coarser than Pool's own per-candidate `authority_level`, a more precise signal that exists upstream but is dropped before `FilledChunk` — flagged to Retriever separately, not fixed here); global 1-based index assigned in slot order.
6. **Telemetry compilation** — `SynthesisTelemetry`: `chunks_in`/`chunks_out`, `duplicates_removed`, `neighbors_added`/`neighbors_skipped_no_anchor`, `unverified_citations`, `planned_status_citations`, `document_name_resolved`/`document_name_fallback`/`document_name_lookup_missed`, `per_slot_verdict`, `per_slot_ride_along`, `compile_ms`, `segment_ms` (DB's ask, 2026-07-24 — `{rerank_ms, neighbor_completion_ms, dedup_ms, name_resolution_ms, citation_build_ms}`, same convention as `pool`'s own segment breakdown). Diagnostics-only, no narrative layer, no raw text beyond what's already in citations (same posture as `pool`'s emit key).
7. **fact_store exclusion from corpus-shaped operations — real crash bug found and fixed (Retriever, 2026-07-24, confirmed live: crashed every single `s`-sourced answer, not a corner case).** `FilledChunk`'s documented vocabulary is "internal" (`document_id` set, `url` None) vs "external" (`url` set, `document_id` None) — but filler_s's `fact_store` chunks are a genuine third category neither binary accounts for: `chunk_id` is *always* a synthetic `fact_<hash>` string (`filler_s.py`'s `_stable_fact_id`, never a UUID), and `document_id` is either the fact store's own source `doc_id` or that same synthetic string. Treating "`document_id` truthy, `url` falsy" as sufficient for "real internal document" sent these synthetic ids straight into `_resolve_document_names`'s `CAST(:ids AS uuid[])` query and `_complete_neighbors`'s `doc_id::uuid` join, both raising `asyncpg.InvalidTextRepresentationError`. **Fixed**: `source_type == "fact_store"` (`_NON_CORPUS_SOURCE_TYPES`) is now excluded from both name-lookup eligibility and neighbor-completion eligibility (same treatment external chunks already got, not folded into either bucket). **Adjacent bug fixed at the same time**: `_infer_authority` used the same flawed `source_type == "internal"` check, which would have labeled a certified, pre-verified Payor Platform fact as `"external"` — the same tier as a lower-confidence web result. Now an explicit allowlist (`_AUTHORITATIVE_SOURCE_TYPES = {"internal", "fact_store"}`), fail-closed for any future source_type this module hasn't seen (consistent with `verified`'s and `document_status`'s posture — default to the more conservative label, not the more permissive one). 4 new regression tests, including one using the *real* (unmocked) `_resolve_document_names`/`_complete_neighbors` with `db=None`, which would raise `AttributeError` outright if the fix were wrong rather than merely failing an assertion. **Polish catch, Retriever's independent live-repro verification, 2026-07-24**: the query-exclusion fix didn't also exclude the logging/counting condition — a fact_store chunk was still firing the "documents-table row may be missing" ops-integrity warning + `document_name_lookup_missed` counter every time, misleadingly, since it was never eligible for a documents-table row to begin with (structurally not-applicable, not a genuine miss). Fixed: that condition now also excludes `_NON_CORPUS_SOURCE_TYPES`. Verified via two new assertions added to the already-existing `test_fact_store_only_shape_does_not_touch_db` (not a net-new test function — Retriever caught an inaccurate "1 more test added" claim in the process, corrected in `synthesis-tracker.md`).
8. **Tech Review's PASS with 3 findings (2026-07-24) — 2 fixed here, 1 routed for coordination.** Full independent code + test verification (43/43 at review time, all read directly, not summarized).
   - **Fixed: neighbor authority edge.** `_complete_neighbors` hardcoded `document_status=None` on every fresh neighbor chunk regardless of its seed's real status — so a neighbor of a PLANNED document read as `authority="authoritative"` via `_infer_authority` (`None != "planned"`), even though the seed itself correctly read `"planned"`. Fixed: neighbors now inherit their seed's `document_status` via a per-slot `document_id -> document_status` map built from that slot's non-neighbor chunks. 2 new tests (planned status inherited; `None` status also correctly inherited, not accidentally coerced to something else).
   - **Fixed: stale contract comment.** `CompiledCitation.source_type`'s inline comment said `"internal" | "external"` only — `fact_store` is a real third value the module's own code (`_NON_CORPUS_SOURCE_TYPES`/`_AUTHORITATIVE_SOURCE_TYPES`) already handles explicitly everywhere else. One-line fix so the contract comment doesn't contradict the code.
   - **Routed, then CLOSED by Observer (2026-07-24) — and it surfaced a real bug beyond deduplication.** `_LLM_UNVERIFIED_REASON = "llm_partial_match"` was hand-mirrored in both `observer.py` and `synthesis.py`, with filler c owning the actual value. Flagged to Retriever/Observer rather than edited here (touches `observer.py`, not Synthesis's file). **Observer's fix**: promoted `ASSIGNMENT_REASON_LLM_RETRIEVED`/`_EXTERNAL`/`_PARTIAL_MATCH` to `fillers/contracts.py` — filler_c.py, observer.py, and synthesis.py all import from there now (`synthesis.py`'s local `_LLM_UNVERIFIED_REASON` removed entirely, `_LLM_CITATION_REASONS` now built from the imported names, semantically identical, verified by direct read — no dangling references, `verified` derivation logic byte-for-byte unchanged). **While investigating "which chunks does this apply to," Observer found their own `_evaluate_llm_retrieval` sufficiency check still used the bare `assignment_reason == "llm_partial_match"` string match — the exact overstated-confidence bug Eval already caught and fixed here (`quote_verified is True`, §9.1) had never been applied to Observer's own verdict logic.** Fixed there too: `chunk.quote_verified is not True`, scoped to LLM-citation assignment reasons only, matching this module's already-established logic exactly. Independently re-verified on Synthesis's side (not just Observer's report): constants confirmed real in `fillers/contracts.py`, no leftover references to the old local constant, `verified`'s derivation logic unchanged, full suite matches Observer's reported count exactly (521 passed/2 skipped). 45/45 synthesis tests still passing.

## 5. What Synthesis does NOT do

- Does not author answer text. Chat does, from `SynthesisResult`.
- Does not call Fillers, Pool, Router, or Observer.
- Does not write to `rag_query_decisions` or any bandit-reward row — Router is the ONE writer (non-negotiable, per `router/persist.py`'s own docstring); Synthesis's only reward-path job is making sure attribution fields (`verified`, `ride_along`, `model_trace`) reach Chat/Eval intact.
- Does not decide continuation, retry, or ladder progression — that's Router's `decide_continuation()`/the orchestrator's loop.
- Does not implement rung retention — see §7.

## 6. Attribution — non-negotiable per Eval (2026-07-24)

Three fields must survive compilation byte-for-byte, never dropped or normalized:
- **`verified`** — per-citation, never collapsed to a slot- or answer-level aggregate. A must_fact backed by a verified chunk grades differently from the same fact backed by an unverified LLM citation (the exact hallucination pattern: real doc/page, fabricated quote).
- **`ride_along`** + the verdict/reason strings — a slot that succeeded because a sibling spent the turn is a selection-biased observation and must stay segmentable in calibration; `EXHAUSTED_BUDGET` (clock cutoff, excluded from calibration) and `EXHAUSTED_ATTEMPTS` (the strategy's own limit, counted as failure) are opposite calibration events and must never collapse to one "didn't finish" state.
- **`model_trace`** (`stage`/`model_used`/`llm_call_id`) — per-slot, threaded through when the caller supplies it (today: not yet, since `orchestrator._run_fillers_simple` discards each rung's `emit`; the parameter exists so this requires no future signature change). `stage` added 2026-07-24 per Eval's explicit ruling: preserve-don't-drop existing attribution (the filler already computed it, passed to its own `generate()` call), not speculative machinery — kept so a future "does model quality diverge by stage" analysis (an accepted v1 limitation on the bandit-live-path) stays possible without a re-plumb. Deliberately excludes latency: Eval ruled that belongs to Timing's `attempt_spans` (`t_attempt_start_ms`/`t_attempt_end_ms`), joined by `call_id`/attempt identity rather than duplicated here — two sources of truth for one number is the anti-pattern this avoids.

## 7. Retention — IMPLEMENTED 2026-07-24, superseding this section's original forward note

`observer-module-spec.md` §8 gated rung retention (superseded fillers' outputs kept, not discarded) on Synthesis's kickoff; this spec's §1 kickoff framing above was written before retention shipped upstream. It has since landed: `orchestrator.py`'s `st["retained_chunks"].extend(filled_slot.chunks)` unions every executed rung's chunks into the slot rather than discarding prior rungs on retry. The "compiled into the answer" vs "retained but not used" distinction this section originally worried about is resolved by construction, not by a new field: Synthesis's fusion step (§4.1) evaluates ALL retained chunks and only chunks MMR actually selects become `CompiledCitation`s — anything fusion drops (`fusion_dropped_redundant`/`fusion_dropped_budget` in telemetry) never reaches Chat or Eval's grading, so retained-but-unused chunks structurally cannot count as recall. No separate "retained but unused" bucket needed.

## 9. Known v1 limitations and tracked v1.1 enhancements — found during sign-off, flagged forward, not fixed here

1. **`verified` overstated confidence for quote-less LLM citations — CLOSED, 2026-07-24, all three legs confirmed live.** `filler_c.py:550`'s `if not cand.quote or quote_verified:` collapsed TWO different epistemic states — quote-given-and-matched (real confirmation) vs. no-quote-given-at-all (nothing to check) — into the SAME `status="retrieved"`/`assignment_reason="llm_retrieved"` outcome. Fixed across three legs: (a) DB added `quote_verified: bool | None` to `FilledChunk` (`fillers/contracts.py:32` — `True`=matched, `False`=given-not-matched, `None`=no quote given); (b) filler c's `_chunk_from_citation` now passes `quote_verified=v.quote_verified` through to the `FilledChunk(...)` construction (previously computed correctly on their internal dataclass but never threaded through — Eval caught this as inert before it landed); (c) Synthesis's `verified` derivation checks `chunk.quote_verified is True` **only for chunks whose `assignment_reason` is one of filler c's LLM-citation reasons** (`llm_retrieved`/`llm_retrieved_external`/`llm_partial_match`) — applying Eval's proposed derivation literally and unconditionally to every chunk would have misread every `a`/`b`/`s` chunk as unverified too, since none of those fillers ever touch `quote_verified`. Non-LLM-citation chunks keep `verified=True` (a direct corpus/service hit, never subject to quote verification). Eval independently re-verified the complete chain end-to-end (confirmed-quote→True, no-quote→False, hallucinated→False). 4 new Synthesis-side tests; filler c added their own directional regression tests plus a real live-call verification.
2. **DDG-sourced external chunks lose a real page title (Filler d's finding, 2026-07-24).** The humanized-URL-path fallback (§4.4c) is confirmed the *correct* choice specifically for Vertex-Grounding-sourced chunks — Vertex's own `title` metadata is by API design just the bare domain, so path-humanization beats it. But DDG-sourced hits carry real, useful page titles (e.g. "Florida Provider Resources | Florida Medicaid | Sunshine Health") that never reach `FilledChunk` — the contract has no `title` field, so filler d drops it before `_chunk_from_passage` builds the chunk. A future `FilledChunk.title: str | None` (best-effort, real titles only, never a bare domain) would let Synthesis prefer it over URL-humanization when present. Contract change, not Synthesis's or filler d's call to make unilaterally — **flagged to Retriever/DB** as a tracked enhancement, not a blocker.
3. **Per-slot telemetry breakdown for multi-slot Diagnostics debugging (UX's ask, 2026-07-24, explicitly deferrable).** UX's sign-off recommended a `per_slot_compile: dict[slot_id -> {chunks_in, chunks_out, duplicates_removed, neighbors_added, verdict, ride_along, unverified_count, compile_ms}]` breakdown for the Diagnostics tab's multi-slot (FAN_OUT) view — today's `SynthesisTelemetry` is aggregate-only for those counters (only `per_slot_verdict`/`per_slot_ride_along` are per-slot). Not implemented: the underlying deltas aren't tracked at per-slot granularity today (e.g. a chunk removed by cross-slot dedup no longer appears in ANY slot's citations, so which slot "lost" it isn't currently recoverable), and plumbing that through `_dedup_cross_slot`/`_complete_neighbors` is a real refactor, not a one-liner — UX explicitly said defer if it adds complexity. Distinct from Eval's earlier "don't duplicate per-slot aggregates in telemetry" position: Eval's concern was calibration (backend, cheap to re-derive from `CompiledCitation.slot_id`), UX's is a rendering convenience where some deltas genuinely aren't reconstructable from the citation list alone. Tracked as a v1.1 enhancement.
4. **`CompiledSlot.model_trace` was missing `stage` — CLOSED, 2026-07-24, Eval ruled field-by-field.** Contract's build (relayed via Chat) surfaced that `model_trace` (then `{model_used, llm_call_id}`) didn't carry `stage` (which filler stage generated the call) or `latency_ms`. Asked Eval directly rather than build either speculatively. **Eval's ruling, applied precisely, not uniformly**: `stage` — YES, add it. This is "preserve, don't drop" existing attribution (the filler already computed it as the value passed to its own `generate()` call), the same class of field as `model_used`/`llm_call_id` that already flow through, not new speculative machinery — kept so a future "does model quality diverge by stage" analysis (an accepted v1 limitation Eval flagged on the bandit-live-path) stays possible without a re-plumb. `attempt_latency_ms` — NO, do not add it: per-attempt latency already lives in Timing's `attempt_spans` (`t_attempt_start_ms`/`t_attempt_end_ms`), which Eval already consumes for calibration latency analysis; duplicating it into `model_trace` would create two sources of truth for one number. If a model needs to be joined to its latency offline, that's `model_trace`↔`attempt_spans` via `call_id`/attempt identity, not duplication. **Implemented**: `model_trace` now `{stage, model_used, llm_call_id}`, threaded through the same `filler_emit_by_slot` pass-through as before — no signature change, no redesign. 1 new test (confirms `stage` passes through and `latency_ms`, even if supplied, does NOT get copied into `model_trace`).

5. **Blend model: CoverageDiagnostic's `saturated` definition corrected post-build, 2026-07-24.** The originally-agreed definition ("ALL contributing strategies fully rejected, none survived into `selected`") is mathematically unreachable given `mmr_select`'s "always keep ≥1 selection" guarantee — the winning chunk in any merge is always drawn from `selected`. Corrected to "strategies with AT LEAST ONE candidate rejected as redundant" (reachable, and per Router's re-confirmation, the semantically-correct signal — marginal frontier exhaustion, not total value). Flagged transparently to Router rather than silently fixed; Router re-confirmed the correction independently. See `fusion.py`'s `derive_coverage_diagnostic` docstring for the reachability proof.
