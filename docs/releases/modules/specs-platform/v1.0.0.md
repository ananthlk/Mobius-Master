# specs-platform v1.0.0

**Commit:** `d518eea` · **Branch:** `main` · **History:** 1 commit (module carve-out), 2026-09-07

## What this module is
specs-platform serves the Mobius Specs Catalog: a single interactive HTML page listing every product spec, governance doc and acceptance criterion, backed by a small Python server that fetches the underlying Markdown from GitHub on demand and renders it in a reader view. It deploys to Cloud Run as service `mobius-specs`. It is a read-only publishing surface — specs are authored in `/docs` and version-controlled in git; this module only presents them.

## What v1.0.0 establishes
- A Cloud Run service (`mobius-specs`) built from `specs-platform/Dockerfile`, running `server.py` on `PORT` (default 8080) with Python's standard-library `HTTPServer` and no web framework.
- A hand-authored catalog page (`index.html`) served at `/`, organising specs by category — governance, surfaces, RAG, agents, design — with per-spec links, status columns and onboarding checklists.
- On-demand spec serving at `/specs/<path>`: the server fetches the Markdown from `raw.githubusercontent.com` and renders it through a built-in Markdown-to-HTML converter, so no spec content is baked into the image.
- A reader view styled with the Mobius design tokens (`--primary: #7c3aed`) including a `prefers-color-scheme` dark variant.
- A Cloud Build pipeline (`cloudbuild.yaml`) tagging images `gcr.io/$PROJECT_ID/mobius-specs:$SHORT_SHA` and `:latest`, intended to trigger on pushes to `main` filtered to `specs-platform/**`.
- A `specs/` symlink to the repo's `../docs` directory, so the catalog's source set tracks the repo without a copy step.
- Operator documentation: `DEPLOYMENT.md`, `CLOUD_RUN_AUTO_DEPLOY.md`, `TEAM_GUIDE.md` and a `status.sh` helper.

## Notable in the run-up
- The catalog page carries roughly 140 spec entries reachable through the `specs/` symlink into `/docs`, covering the RAG module specs (shape gate, reformat, structure, slots, pool, router, observer, synthesis), product docs, and the AHCA sprint dashboards.
- The escape-then-render Markdown converter handles headings, lists, fenced code blocks and inline bold/italic/code, escaping HTML before substitution so spec content cannot inject markup into the reader view.
- Serving specs from GitHub raw rather than from the container image means a spec edit is visible without redeploying — the Dockerfile deliberately copies only `index.html` and `server.py`.
- Request logging is suppressed (`log_message` is a no-op), so the service produces no per-request access log.

## Contracts other modules depend on
- Cloud Run service name `mobius-specs`; the container listens on `PORT` (default 8080) and serves `GET /` and `GET /specs/<path>`. Any other path returns 404.
- `/specs/<path>` maps directly onto a path under `GITHUB_RAW` = `https://raw.githubusercontent.com/ananthlk/Mobius-Master/service-line-registry/docs`. The repository, the branch name `service-line-registry`, and the `docs/` layout beneath it are all part of the contract: renaming or moving a doc under `/docs` breaks its catalog link.
- Links in `index.html` are hardcoded paths such as `/specs/product-docs/mobius-thesis.md` and `/specs/rag-agents/retriever-fleet-schematic.md`; the catalog and the docs tree must be kept in step by hand.
- Cloud Build image names `gcr.io/$PROJECT_ID/mobius-specs:$SHORT_SHA` and `:latest`, built with `-f specs-platform/Dockerfile` from the repository root.
- The container is deployed `--allow-unauthenticated`, so every consumer reaches it as an anonymous public URL.

## Known gaps carried into v1.0.0
- The service is deployed `--allow-unauthenticated` and serves internal product, architecture and go-to-market specs with no access control of any kind.
- The GitHub raw base URL is hardcoded to a non-default branch (`service-line-registry`) of `ananthlk/Mobius-Master`. Specs merged to that repo's default branch are not what this service shows, and there is no configuration knob to repoint it.
- Every `/specs/` request makes a live outbound fetch with a 5-second timeout and no caching; GitHub being slow, rate-limiting, or the path being wrong all surface identically as a bare 404, since the fetch is wrapped in a blanket `except`.
- There are no tests, and the Markdown converter is a hand-rolled line-based parser that silently mis-renders anything outside the handful of constructs it recognises (tables, links, nested lists, blockquotes).
- `cloudbuild.yaml` contains two overlapping deploy steps — a `gke-deploy` step and a `run deploy` step described in its own comment as the "alternative simpler approach" — so the pipeline as written attempts both.
- `index.html.bak` is checked in beside the live page, and the catalog's status columns are maintained by hand, so the catalog can assert a spec status that no longer matches the spec.
