# mobius-payor v1.1.0

**Commit:** `1e8e5b8` · **Branch:** `claude/sources-module-canonical-payor-enumerate` · **Since v1.0.0:** 11 commits, 2026-09-07 → 2026-09-07

## Why this is a MINOR

Nothing that existed at v1.0.0 changed shape. Every route added here is new (`/research/console`, `/api/research/*`), the one pre-existing address is preserved rather than removed — `/research-console` is a 307 to `/research/console`, which the browser follows carrying the `#request-<id>` fragment unchanged, so existing deep links from `/service-lines` still resolve — and the single migration (067) creates a new table. The change a consumer must know about is not a break in this module's own contract but a policy tightening: `/api/research/overview` and `/api/research/request/{id}` now require a verified identity, so any unauthenticated caller of those reads (they were open for part of this range) will get a 401. That is flagged below rather than treated as MAJOR because those endpoints are new in this same range and had no released consumer at v1.0.0.

## What changed

- **The research console is served live.** It was a generated snapshot file baked into the image; `/research/console` is now a shell fed by `/api/research/overview` and `/api/research/request/{id}` reading `research.*` on request, with a 20s refresh that updates the queue, counts and cost but never the open detail. The two competing routes were collapsed to one URL.
- **Identity is delegated to mobius-user, not implemented here.** `app/research_identity.py` calls `POST /api/v1/auth/verify`; this module holds no `JWT_SECRET` and decodes nothing. The `/auth/me` fallback was removed once User Manager confirmed `/verify` live, because a rollback of mobius-user would otherwise have silently downgraded the check — a missing `/verify` is now a 503 and nothing is recorded. `{"valid": false}` on a 200 is still checked, deliberately failing closed.
- **Reads are gated too, and there is now a way in.** A signed-out reader is bounced once to the fleet sign-in and returns with a single-use 60-second code redeemed server-side; no credential goes in a URL, and an earlier `#t=` bearer-in-fragment cut was replaced (a test fails if `#t=` returns). A service that is merely down is never bounced.
- **A person can overrule the judge.** `research.judge_override` (067) records, per refused field, whether the person upheld the refusal, approved the extractor's value, or supplied a correction — keeping the judge's verdict, quote and reason verbatim alongside what the person did. Uphold is the default and there is no bulk action; a CHECK constraint refuses a correction with no value. This is distinct from `/grant`, which unblocks a machine waiting on time, budget or authority.
- **The decision is an API contract, not a dialog.** `GET /api/research/decisions[?consumer=]` and `POST /api/research/decide` expose what is waiting and record a choice; the console is one client of that. `/decide` validates `chose` against the options actually offered on that row and refuses one that was never on the table.
- **`chose` was being dropped on insert.** The console had always sent the option id and `/rule`'s INSERT had always discarded it, so every ruling landed with `chose=NULL` and the machine had nothing to branch on. Fixed, and `what_happens` was backfilled onto the 12 rows already carrying options.
- **Two production defects fixed.** `NameError: name 'via' is not defined` returned a 500 from every `/api/research/request/{id}` to signed-in readers — every existing test covered rejection paths, which raise before that line, so the one branch a real reader takes was untested; tests now walk through the gate. Separately, asyncpg returns jsonb as TEXT where psycopg2 parses it, which silently blanked the judge verdict card and then the decision dialog's options; `_rows` now warns when a JSON-shaped string arrives in an undeclared column.
- **`pytest tests/` was running zero tests.** Two script-style files exited during collection, aborting the session with an INTERNALERROR while printing "no tests ran". Moved under `__main__` and each exposed as a real test: 0 → 87 passing.

## New or changed contracts

- New routes: `GET /research/console`; `GET /api/research/overview`, `/api/research/request/{rid}`, `/api/research/whoami`, `/api/research/refused/{diagnosis_id}`, `/api/research/decisions`; `POST /api/research/signin`, `/acknowledge`, `/rule`, `/grant`, `/override`, `/decide`.
- `GET /research-console` now returns 307 → `/research/console` (was an HTML page).
- New table: `research.judge_override` (migration `067_judge_override.sql`).
- New env vars read by `app/research_identity.py`: `MOBIUS_USER_URL`, `MOBIUS_USER_INTERNAL_KEY`, `MOBIUS_SIGNIN_URL`.
- Upstream dependency added: `POST /api/v1/auth/verify` on mobius-user is now required — there is no fallback.
- Reads under `/api/research/*` require a verified identity; unauthenticated callers get 401 (503 when mobius-user is unreachable).

## Known gaps carried forward

- `app/routers/_research_console_page.py` is a generated artefact of mobius-skills' `deep_research.console` checked into this repo. It is only as fresh as the last regeneration plus deploy, and a hand-edit to it has already caused one live drift.
- Ownership of the console is explicitly temporary: the seam is that mobius-skills owns what happened inside the machine and this module owns which requirement needed sourcing and whether its citation holds. `e2c4f0e` records the intent to point elsewhere the day Deep Research serves the page itself.
- Gating is on verified identity only, not on role. Roles and capabilities are recorded but nothing enforces them yet.
- `_JSONB` remains a hand-kept allow-list of jsonb columns; the new warning surfaces a missing entry at runtime but does not remove the manual list.
- The working tree on this branch carries uncommitted migration files not covered by this release.
