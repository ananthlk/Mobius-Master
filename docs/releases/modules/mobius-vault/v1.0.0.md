# mobius-vault v1.0.0

**Commit:** `a434e85` · **Branch:** `main` · **History:** 9 commits, 2026-07-13 → 2026-08-20

## What this module is
My Vault is the user's personal workspace surface for Mobius Chat: recent threads, liked answers, tasks and uploaded documents aggregated in one place with per-item actions. It ships as a dependency-free static SPA that reads the Mobius platform token and calls the chat backend's `/chat/*` endpoints. It replaces the two separate chat-sidebar sections ("Recent searches" and "Most helpful searches") with one workspace.

## What v1.0.0 establishes
- A full-page vault (`vault.html` + `static/vault.js`) covering four live tabs — Recent, Liked, Tasks, Uploads — each backed by a named chat endpoint.
- The same files run in two serving modes with no code change: same-origin under mobius-chat at `/vault`, or as a standalone origin where the launching tile forwards the token in the URL fragment (`#t=…`), which the SPA reads once then strips.
- A mountable panel build (`static/vault-panel.js`) that docks into chat via `window.MobiusVault.open/close/toggle`, the `window.mobiusOpenVaultPanel(tab)` shim, and the `#vaultPanelMount` host element.
- A 7-section panel model that mirrors the chat sidebar's section pool and shares its pin preference, so the two surfaces do not diverge.
- Actionable operations: bulk select, task scheduling / reassign / create, use-in-chat, upload extend-TTL and delete, download and open-thread.
- An auth gate: the panel is gated when unauthenticated, fires a one-shot access beacon post-auth, and signed-in users always get real data rather than the sample dataset.
- A conditional urgency strip that appears only when something is actionable (uploads expiring within three days, tasks due today or overdue), with per-tab counts left to the rail.
- Vendored Mobius design tokens (`static/mobius-tokens.css`) plus self-contained preview and mockup pages for demo and for Chat's sidebar work.

## Contracts other modules depend on
- Chat backend reads: `GET /chat/whoami`, `GET /chat/history/threads`, `GET /chat/history/most-helpful-searches`, `GET /chat/tasks?status=open&assignee=…` and `&org_name=…`, `GET /chat/uploads?user_id=…&include_inactive=true`.
- Chat backend writes: `POST /chat/tasks/{id}/{action}`, `GET /chat/uploads/{id}/download`, `POST /chat/uploads/{id}/extend {days}`, `DELETE /chat/uploads/{id}`.
- Usage ledger: `POST /api/v1/users/access-beacon`, fired once per session after auth.
- Browser globals the host page must honor: `window.MobiusVault` (`open`, `close`, `toggle`, `isOpen`), `window.mobiusOpenVaultPanel(tab)`, `window.mobiusCurrentThreadId`, `window._mobiusSuiteTiles` (shared tile source of truth with the sidebar), `window.MOBIUS_CHAT_API_BASE` (API base for cross-origin mode).
- DOM seam: chat provides `#vaultPanelMount` between `<aside>` and `<main>` for docked mode.
- Deep-link shape: thread navigation goes to `<chat origin>/?thread=<id>`.
- Token transport: `localStorage` in same-origin mode; URL fragment `#t=<token>` in standalone mode; all calls carry a Bearer header.
- Env: `MOBIUS_VAULT_URL` is the tile target for the standalone deployment.

## Known gaps carried into v1.0.0
- Three rail tabs are ghosts, not features: Bookmarks, Saved reports, My feedback. The last one waits on a per-user `GET /chat/product-feedback` the feedback agent has not built.
- "Promote to corpus" on upload rows is disabled and blocked on the org doc-store.
- Extend-TTL and Delete depend on Instant RAG endpoints; the UI degrades to a "not live yet" message when they are absent, so the actions are not guaranteed live.
- The "My org's tasks" bucket needs `org_memberships` on `/chat/whoami`, an open ask on the Chat agent; without it that section stays dark.
- Standalone-origin mode is untested in production: it requires CORS on the chat API, and the module is presently deployed as files inside mobius-chat rather than as its own origin.
- The upload delete path uses `window.confirm` in `vault.js`, which is blocked inside iframes; only the panel build has an in-panel confirm.
- There is no automated test suite — verification is a manual test plan at `docs/vault-page-test-plan.md`.
