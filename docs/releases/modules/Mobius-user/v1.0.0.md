# Mobius-user v1.0.0

**Commit:** `cef1a10` · **Branch:** `main` · **History:** 52 commits, 2026-02-02 → 2026-09-07

## What this module is
Mobius-user is the shared authentication, identity and profile service for the Mobius fleet. It owns its own PostgreSQL database (`mobius_user`) and exposes a FastAPI service, deployed to Cloud Run as `mobius-user`, that other surfaces call for sign-in, token verification, user profiles, preferences and org membership. It is also importable as a Python package (`mobius_user`) with Flask and FastAPI route blueprints for modules that embed it directly.

## What v1.0.0 establishes
- A standalone Cloud Run service (`app/main.py`) mounting three routers: `/api/v1/auth`, `/api/v1/admin`, `/api/v1/users`.
- Password and Google-SSO authentication with JWT access/refresh tokens, plus a server-side verifier endpoint (`POST /api/v1/auth/verify`) so other services do not each re-implement token checking.
- A user profile and preferences envelope on `/api/v1/auth/me`, with a deterministic profile builder and per-field preference audit history.
- An identity directory: agent principals, aliases, org memberships resolved against the canonical org registry, plus org-scoped roster and `@`-mention directory endpoints.
- Account lifecycle primitives — invite, set-password, password reset, membership approval, soft removal, deactivation/reactivation, and revocable per-user capabilities.
- Cross-origin hand-off (`/api/v1/auth/handoff/mint` and `/handoff/redeem`) so a session established in chat can be passed to another surface.
- An access-event ledger and an admin Users & Usage console served at `/admin` and `/admin/usage`.
- Eleven Alembic migrations (`001`–`011`) defining the `mobius_user` schema.

## Contracts other modules depend on
- HTTP surface on Cloud Run service `mobius-user`:
  - `GET /health`, `GET /api/v1/public-config`, `POST /api/v1/access-beacon`
  - `/api/v1/auth/*`: `register`, `login`, `google`, `refresh`, `logout`, `me`, `verify`, `check-email`, `token-info`, `activities`, `set-password`, `password-reset/request`, `password-reset/confirm`, `handoff/mint`, `handoff/redeem`, `onboarding` (PUT), `preferences` (PUT)
  - `/api/v1/users/*`: `resolve`, `by-identity`, `directory`, `access-beacon`, `pending-memberships`, `org/{org_slug}/members`, `{user_id}`, `agents`, `invite`, `{user_id}/aliases[/{alias}]`, `{user_id}/orgs/{org_slug}` (PUT/DELETE) and `/approve`, `/remove`, `/restore`, `{user_id}/deactivate`, `{user_id}/reactivate`, `{user_id}/capabilities[/{capability}]`
  - `/api/v1/admin/*`: `users`, `users/{user_id}`, `usage/summary`
- Database `mobius_user`, tables created by migrations 001–011: `tenant`, `role`, `app_user`, `auth_provider_link`, `user_session`, `activity`, `user_activity`, `user_preference`, `user_preference_audit`, `user_alias`, `user_org_membership`, `auth_token`, `user_access_event`, `user_capability`.
- Cross-module references are by `user_id` (UUID) only — no cross-database foreign keys.
- Env vars consumers or the deploy set: `USER_DATABASE_URL`, `JWT_SECRET` (must match across every app sharing auth), `JWT_ACCESS_TOKEN_EXPIRE_MINUTES`, `JWT_REFRESH_TOKEN_EXPIRE_DAYS`, `DEFAULT_TENANT_ID`, `DEFAULT_TENANT_NAME`, `CORS_ALLOW_ORIGINS`, `GOOGLE_CLIENT_ID`, `MOBIUS_EMAIL_SKILL_URL`, `MOBIUS_ROSTER_URL`, `MOBIUS_SET_PASSWORD_URL_BASE`, `MOBIUS_USER_ADMIN_EMAILS`, `MOBIUS_INVITE_GOOGLE_ACTIVATION`.
- Outbound dependencies: the email skill (`MOBIUS_EMAIL_SKILL_URL`) for invite/reset mail, and the master org registry (`MOBIUS_ROSTER_URL`, `POST /org/resolve`) for canonical `org_slug` resolution.
- Python package seams for embedding modules: `mobius_user.db.init_db`, `mobius_user.get_auth_service`, the `UserProfile`/`AuthEnvelope` shapes, and the Flask/FastAPI auth routers.

## Known gaps carried into v1.0.0
- Admin authorization is an email allowlist in `MOBIUS_USER_ADMIN_EMAILS`; the deploy config itself notes that a proper `is_admin` column on `app_user` is deferred to v2.
- `CORS_ALLOW_ORIGINS` defaults to `*` when unset, so a deploy that forgets the variable is open to any browser origin. The allowlist is also a hand-maintained list of Cloud Run URLs that has needed a commit each time a new surface appeared.
- The dev deploy pins a `DEFAULT_TENANT_ID`/`DEFAULT_TENANT_NAME` convenience tenant; real tenant provisioning is not part of this release.
- Test coverage is a single file (`tests/test_account_lifecycle.py`) against a service with roughly forty endpoints; auth, hand-off, admin and directory paths have no automated tests here.
- The service both hosts admin HTML pages (`/admin`, `/admin/usage`) and serves the API from the same origin and process; there is no separation between the operator console and the machine API.
