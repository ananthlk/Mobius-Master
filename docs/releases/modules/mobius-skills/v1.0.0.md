# mobius-skills v1.0.0

**Commit:** `5adc343` · **Branch:** `main` · **History:** 299 commits, 2026-03-13 → 2026-09-07

## What this module is

mobius-skills is the monorepo of independently deployed capability services that the rest of
Mobius calls — each subdirectory is its own service with its own Dockerfile and deploy script.
It holds the fleet's web-egress path (web-scraper), the fact-establishing state machine
(deep-research), the appeals agent, the PHI classifier, doc-reader, provider-roster
credentialing, task-manager, and the healthcare/search/org-intelligence lookups.

## What v1.0.0 establishes

- A single compliant web-egress path for the fleet: `web-scraper` with a robots gate, honest
  MobiusBot identification, per-host politeness throttling with `Crawl-delay` support, and
  `/fetch/batch` as the shared fetch entry point.
- A crawl that is accountable: conservation accounting, per-object push states with a write-back
  endpoint and retry, `completed_with_errors` as a real terminal state, a suppressed-files
  export, and provenance so every file carries the page that linked it.
- `deep-research` as a general fact-establishment service — the caller supplies the question and
  a required `evaluator_prompt`, the skill asks chat's ReAct loop with a new thread per turn,
  checks grounding rather than trusting it, and diagnoses *why* a rejection happened before
  choosing a repair.
- A named-state machine for research runs: turns, repairs, resume-on-acquire, halt as a state the
  machine knows, an owner queue with polarity, and a Recorder that writes the ledger as the run
  happens.
- The appeals stack: CARC catalog, streaming rule generation with a rules library, a question
  bank and confidence ladder, payor-agnostic canonical content with tri-state composition, and a
  bulk driver that persists generated payor facts.
- A PHI classifier that gates on strong identifiers only, with containment matching and a
  business-noun allowlist merged from a lexicon endpoint.
- Provider-roster credentialing with an MCP tool surface (29 tools as of the August work) and a
  platform auth gate on its pages.

## Notable in the run-up

- deep-research took its authority model apart and rebuilt it: authority is the caller's policy,
  a passing authority is not a verdict, a lookup failure is not an authority verdict, and the
  gate that was supposed to enforce it was found never to have run.
- The judge now states what it checked, `perform_turn` emits a ledger, citations are ones a
  reviewer can actually follow, and the corroboration step reads the document it judges.
- A verifier and reader that can see a table — table-bearing evidence stopped being invisible to
  extraction and corroboration.
- `robots.txt` handling: a missing robots.txt had meant DENY since March; it now correctly means
  ALLOW, and the earlier "enforcement" refusals were re-diagnosed as that default-deny bug.
- Scraper correctness under load: GCS blob names disambiguated per source URL to kill filename
  collisions, wire-safety tested across all 185 encoding fixtures (raw spaces, double spaces,
  parens, pre-encoded `%20`, no double-encoding), and a CPT licence screen added on the download
  path.

## Contracts other modules depend on

- **web-scraper HTTP:** `POST /scrape`, `GET /scrape/{job_id}`, `GET /scrape/{job_id}/stream`,
  `POST /scrape/{job_id}/push-report`, `/scrape/review`, `/jobs/active`, `POST /fetch/batch`,
  `/health`. `document_types=[]` means download nothing, not download everything.
- **Scraper → RAG provenance sink:** scraped-page results are posted to mobius-rag's
  `/scrape-provenance` and imported via `/documents/import-scraped-pages`; every file carries
  `source_page_url`, the page that linked it, plus an `external_run_id`.
- **deep-research invocation:** `POST /api/skills/v1/research` with `{consumer, subject_id,
  question, evaluator_prompt}`. `evaluator_prompt` is required — the skill deliberately refuses to
  supply a generic evaluator for someone else's fact store.
- **deep-research schema (shared DB):** migrations `045_deep_research`, `046_discovery_seam`,
  `047_research_turns`, `053_repair_retry`, `054_resume_on_acquire`, `055_halt`,
  `056_owner_queue_and_polarity`, `057_owner_vocabulary`, plus `sql/loop_state.sql`. Repairs are
  filed to `research.diagnosis`; consumers read this provenance rather than building their own.
- **Chat tool names** backed by services here: `web_scrape`, `healthcare_query`,
  `healthcare_npi_lookup`, `document_upload_skill`, and the `appeals_*` family
  (`appeals_find_carc`, `appeals_lookup_rules`, `appeals_get_playbook`, `appeals_validate_claim`,
  `appeals_assemble_letter`).
- **Payor fact-store adapter:** the appeals adapter writes to the agreed payor fact-store
  contract and returns a distinct `resolver_unavailable` reason code.
- **Credentialing MCP tools**, including `search_clinician_by_name`, and the rate/benchmark tools
  with structured extra blocks (`get_org_rate_gap` takes `include_msa_cut`).
- **Directory layout is itself the contract:** each subdirectory deploys as its own service, so
  moving or renaming one changes a deploy target.

## Known gaps carried into v1.0.0

- `instant-rag` is deprecated in place — the directory contains only `DEPRECATED.md`. Callers
  expecting a service there will find none.
- `chat-document-upload` and `fl-medicaid-npi` carry no deploy scripts or Dockerfiles; they are
  not independently deployable the way the rest of the monorepo is.
- deep-research's authority model changed repeatedly in the final three weeks, including one
  commit marked PROVISIONAL (authority by document metadata rather than filename). It is not a
  settled contract.
- The web-scraper's robots default-deny bug went undetected from March until August. Any coverage
  or compliance claim measured before that fix reflects the bug, not the sites' actual policies.
- The `email/` service depends on an operator-supplied `credentials.json` that is correctly
  gitignored and has never been committed — but it is therefore undeclared infrastructure: the
  service will not run without a file that no manifest names. Its auth handling has also not been
  brought in line with the platform auth gate applied to the credentialing surfaces.
