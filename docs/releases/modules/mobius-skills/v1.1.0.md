# mobius-skills v1.1.0

**Commit:** `42acd2f` · **Branch:** `main` · **Since v1.0.0:** 15 commits, 2026-09-07 → 2026-09-07

## Why this is a MINOR

Everything added here is additive at the seams a peer module can see. The five new schema files (058–062) only `add column if not exists` to `research.request` / `research.resolution` and create new tables and views (`research.llm_call`, `research.model_rate`, `research.resolution`, `research.ruling`, `research.deadline_policy`, `research.action_deadline`, and the `request_cost` / `actor_cost` / `unresolved` / `stalled` / `due_now` / `overdue` views) — no column another module reads was dropped or retyped. The one thing a consumer should read before upgrading is the acceptance-semantics change in `56751af`: `accepted` is now `bool(kept)` with a separate `meets_required` flag, so a request whose `--required` list was unsatisfiable can now come back `accepted` where it previously came back `not_answered`. That is a behaviour change for anyone branching on `accepted`, not an API break, so it is called out below rather than treated as a MAJOR.

## What changed

- **Authority moved onto the request.** `perform_turn` was passing `rule_ref=None, authority="any_cited"` as literals, so the §14 authority gate was never armed on the path the runner drives. Authority, `authority_policy` and `rule_ref` now live on `research.request` (058), and `modes.policy_for()` is the single word→policy mapping used by both `run_batch` and `perform_turn`.
- **Per-call cost capture.** `llm()` already returned provider/model/token counts/latency and every call site discarded them. `research.llm_call` records one row per call, attributed via a contextvar; `research.model_rate` holds published prices as data so `cost_cents` is NULL (and flagged unpriced) rather than fabricated when no rate exists.
- **Resolution as a predicate, not a notification.** `research.resolution` and `research.ruling` (060) plus the closure contract (061) give every open question a machine-evaluable path in one of four kinds — `automatic`, `observable`, `ruling`, `overrule` — with `research.stalled` / `research.due_now` as the invariant that no request sits with no path. The commit reports 21 closed of 47, 0 with no path.
- **Two clocks and planned deadlines.** `research.overdue` (062) separates the task clock (someone else's SLA, with `acknowledged_at` distinguishing "unlooked at" from "taken and stuck") from the question clock (always ours). `plan_deadline()` works backward from when the answer is owed and returns `infeasible` with the arithmetic when that lands in the past.
- **Human tasks must justify themselves.** `NEEDS_A_PERSON` names the five lines the machine may not cross alone (authority, assert_negative, spend, give_up, cross_team); anything else the machine can perform, it performs. The commit reports 9 of 12 queued human tasks needed nobody.
- **A ruling now does what its option says.** `sweep()` branches on the chosen option id (`stop` / `genuinely_silent` are terminal → `abandoned` with the reason in `quiet_because`), and `what_happens()` is generated from the same `TERMINAL` set that `sweep()` reads, so page, API and log all render one sentence rather than each composing its own.
- **Extractor and critic corrections.** The extractor is now forbidden from converting units to fit a schema's vocabulary (the Molina "one (1) year" → "12 months" case); the critic names `hedged` and `about_a_document` as distinct issues; and a critic parse failure is `supported: None` with `critic_did_not_run` rather than `supported=False` — the recurring could-not-check vs. checked-and-false conflation.
- **Console generator and identity.** `console.py` is one generator for both the file-backed and served pages, with `LIVE_SWAP_FROM/TO` asserted on both sides (including that `boot()` is defined *and* called). The page reads the fleet session instead of asking for a typed name, and `language.py` maps internal terms to reader-facing words shipped alongside the data via `research.language`.

## New or changed contracts

- `research.request`: new columns `authority`, `authority_policy` (jsonb), `rule_ref` (058); closure columns `due_at`, `next_action_at`, `quiet_because` (061).
- `research.resolution`: new table (060), extended with acknowledgement/deadline columns (061, 062).
- New tables: `research.ruling`, `research.llm_call`, `research.model_rate`, `research.deadline_policy`, `research.action_deadline`.
- New views: `research.unresolved`, `research.stalled`, `research.due_now`, `research.overdue`, `research.request_cost`, `research.actor_cost`.
- `critique()` gains a `known=` input (CLI `--known payer=sunshine_fl`), recorded as `check="given"` with no quote or document and excluded from the judged count.
- Behaviour change, not shape: `accepted` no longer folds in the required-field check; `meets_required` reports it separately.
- No new HTTP endpoint in this module. The deep-research FastAPI app (`deep_research/main.py`) is unchanged across this range.

## Known gaps carried forward

- The console page is *generated* here but *served* by mobius-payor from a checked-in copy (`app/routers/_research_console_page.py`). Regeneration and deploy are two steps in two repos; drift between them is possible and has already happened once (a hand-added `boot()`).
- `standard_requirement` subjects still carry a bare requirement id; the join key was ratified in the sourcing contract but is not built, so those rows fall back to the question's first clause and render "not yet named".
- Cost coverage is thin: the console panel explicitly reports measured-call coverage because early samples were as small as one call, and any model without a `research.model_rate` row totals as an unpriced floor.
- Rulings written before the option id was persisted are classified from their opening words; ones that cannot be read are left unclassified rather than guessed.
