## What this module is
An MCP server that exposes Mobius skills as callable tools over streamable HTTP. It is the adapter layer between MCP clients (Cursor, chat clients) and the Mobius service fleet — web search and scraping, healthcare/NPI registry lookups, provider credentialing, corpus retrieval, email, chat document uploads, and the Payor Fact Store. It owns no business logic of its own; each tool formats arguments, calls the owning service, and renders the response as text.

## What v1.0.0 establishes
- A single `FastMCP` server (`app/server.py`, ~2,200 lines) started with `python -m app` over `streamable-http`, default endpoint `http://localhost:8006/mcp`.
- Organization and provider identity tools: `search_org_names`, `search_org_by_address`, `find_org_locations`, `find_associated_providers_at_locations`, `org_npi_lookup`, `healthcare_query`.
- Credentialing tools: `provider_roster_credentialing_report` and `check_provider_credentialing` (NPI + org profile via the credentialing profile endpoint), the latter with a dedicated test file.
- Retrieval tools added as a group: `corpus_search`, `lazy_corpus_search`, `thread_corpus_search`.
- An email tool group with explicit send-safety arguments: `email_send`, `email_craft_send`, `email_prepare`, `email_status`, `email_suppress`.
- Delegation of shared skill implementations to `mobius_skills_core` (google_search, web_scrape, healthcare_query, upload), leaving this repo as routing plus response formatting, with canonical tool names.
- Payor Fact Store access as the final capability: `payor_fact(payor, predicate)` and `payor_facts_list(payor, domain)`, returning accepted facts only, with authority inheritance handled by mobius-payor.

## Contracts other modules depend on
- **MCP tool names** — every `@mcp.tool()` function name is a public contract for MCP clients: `google_search`, `web_scrape`, `search_org_names`, `search_org_by_address`, `find_org_locations`, `find_associated_providers_at_locations`, `healthcare_query`, `org_npi_lookup`, `provider_roster_credentialing_report`, `check_provider_credentialing`, `document_upload`, `list_thread_uploads`, `corpus_search`, `lazy_corpus_search`, `thread_corpus_search`, `profile_org`, `get_org_report`, `email_send`, `email_craft_send`, `email_status`, `email_suppress`, `email_prepare`, `payor_fact`, `payor_facts_list`.
- **Transport** — streamable-HTTP MCP at `/mcp`, port from the server's configured port (8006 by default). Client configs (`.cursor/mcp.json`) point at this URL.
- **Upstream endpoints called** — provider-roster-credentialing `/report`, mobius-chat `POST /chat/roster-upload` and `GET /chat/thread/{id}/uploads`, and the mobius-payor fact endpoints. Changing those breaks tools here, not the other way round.
- **Environment variable names** — `CHAT_SKILLS_GOOGLE_SEARCH_URL`, `CHAT_SKILLS_WEB_SCRAPER_URL`, `CHAT_SKILLS_PROVIDER_ROSTER_CREDENTIALING_URL`, `CHAT_API_BASE_URL`, `CHAT_SKILLS_PAYOR_FACT_STORE_URL`.
- **Python dependency** — `mobius_skills_core` is imported directly for the delegated skills; its module paths are a build-time contract.

## Known gaps carried into v1.0.0
- Test coverage is three files (`test_server_tools.py`, `test_check_provider_credentialing.py`, `test_payor_fact_store.py`) against ~24 tools; most tools have no test.
- Responses are formatted as human-readable text strings, not structured JSON, so downstream consumers parse prose.
- Calls use `urllib` with per-call environment-variable URLs; there is no shared retry, circuit-breaking, or auth layer across tools.
- The Payor Fact Store URL defaults to a hard-coded deployed dev Cloud Run hostname; local or production use requires an explicit override.
- `web_scrape` forwards `scrape_mode` to the scraper API, but the README notes legacy scrapers may ignore the extra fields and return a single page regardless — the depth/page limits are not enforced here.
