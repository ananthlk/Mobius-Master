# mobius-rag v1.0.0

**Commit:** `53f6178` · **Branch:** `retriever-answer-engine` · **History:** 579 commits, 2026-01-28 → 2026-09-06

`retriever-answer-engine` is the live state and sits 201 commits ahead of `main`.

## What this module is

mobius-rag is the retrieval and corpus module. It takes documents in from uploads, GCS, Google
Drive, HTML and scraped pages; extracts, chunks, classifies, tags and embeds them; and serves
retrieval and answering to callers such as chat. Alongside the pipeline it carries the operator
consoles that make the corpus legible — Corpus Health, Pipeline, and a single-page Eval portal.

## What v1.0.0 establishes

- A multi-inlet ingest pipeline with a transaction ledger — one row per **attempt**, on every
  path (upload, GCS, Drive, HTML, scraped pages, reingest) — so failures and rejections are
  counted, not just successes, and each failure carries a typed cause.
- Chunking and embedding as separate worker services off the API request path, with per-document
  job control (start/stop/restart/kill-and-reset), event streams, and a publish boundary that
  enforces minimum substance.
- Retrieval over pgvector with per-request token and latency budgets, page-number threading
  through fillers, passenger-table attachment with breadcrumb and page-proximity fallback, and a
  router that holds the expensive strategies out of round one.
- A policy/lexicon layer: `policy_paragraphs` and `policy_lines`, a lexicon candidate catalog
  with bulk review, and chunk-level tag backfill.
- A duplicate/versioning gate: text-overlap duplicate determination, typed pair resolutions,
  a federated `/corpus/duplicates` surface for the Payor platform, and an executor that turns a
  human decision into a real re-chunk.
- Operator consoles built on the pipeline's own telemetry: Corpus Health (sources, stages,
  gating vs enriching classifiers, stopped vs stuck, time-to-serve), a Pipeline tab with cohort
  accounting and reconciliation, and a unified Eval portal at `/eval` with Run/Browse/Compare.
- Reference-free grading (`grounding_only`) alongside gold-answer grading, plus a locked-ruler
  parity guard so console runs and bank runs are comparable.

## Notable in the run-up

- Ingest provenance: `source_page_url` accepted so a file carries the page that linked it, then
  provenance parity enforced across all three import inlets.
- Product-line authorship settled — the Fact Store's verdict is persisted by RAG as scribe, not
  author, with the ratified Sunshine mapping as derivation only.
- Database hardening: per-event-loop asyncpg engines (one pool cannot serve two loops), pools
  sized per workload with a fleet-size assertion, and a worker watchdog rewritten so that work,
  not events, is the liveness signal.
- Table capture wired at the extraction seam and persisted across all six PDF ingest paths,
  scoped to HCPCS Level-II codes, with `document_tables` FK-enforced to page provenance.
- ORM drift closed — the models were missing twelve columns the database had carried for weeks.

## Known gaps carried into v1.0.0

- The live state is a feature branch. `retriever-answer-engine` is 201 commits ahead of `main`;
  anything reading `main` is reading a stale module.
- `PATH_B_STATUS.md` records that Path B — the deterministic policy pipeline that writes
  `policy_paragraphs`/`policy_lines` and identifies lexicon candidates — is incomplete or missing
  in this repo relative to its intended behavior.
- `STATUS.md` is stale: it describes Step 6 (PDF extraction) as the current frontier and lists
  blockers from a much earlier phase. It is not a usable statement of module state.
- Router escalation is calibrated only partly. Commits record holding strategies c and d out of
  round one unconditionally as a correctness measure, not as a tuned policy.
- Corpus-health reconciliation and cohort accounting were repeatedly corrected during the run-up
  (window definitions, stage ordering, stopped-vs-not-reached). The counts are trustworthy only
  for the windows explicitly implemented.
- The nightly orchestrator (`app/nightly_orchestrator.py`, `app/nightly_infra.py`) is exposed via
  `/admin/nightly/*` but its infrastructure layer has open work carried from the nightly pipeline
  track.
