# mobius-interact v1.0.0

**Commit:** `aa6767d` · **Branch:** `main` · **History:** 15 commits, 2026-07-08 → 2026-07-19

## What this module is
mobius-interact is the web-interaction engine: the "hands" that operate a webpage from a declarative instruction set (find, highlight, click, type, wait, read, assert, navigate). Content always comes from a feeder — another module publishes a script; this engine validates, stores, serves, and executes it. It ships a FastAPI registry service plus an in-page runner (`/runner.js`) that drives a page in guide or narrate mode.

## What v1.0.0 establishes
- The `interact.v1` schema (`app/schema.py`): script metadata plus ordered steps, with the `Mode` (guide/narrate/auto), `Action`, and `Permission` enums as the fixed vocabulary.
- A normative validator (`app/validator.py`) enforcing anchor tiers, permission gating, and input templating as cross-field rules rather than shape checks.
- A registry service (`app/main.py`) that lets feeders publish over HTTP without redeploying the engine — validate, publish, list, fetch by id or natural key, and unpublish.
- Persistence with startup auto-migration for Postgres (`migrations/001`–`003`), covering the script registry, version/provenance columns, and run records with duration and abort reason.
- An in-page runner (`runner/interact-runner.js`) with a DOM fixture demo, brand-token CSS, `wait_for` meaning present-and-visible, and collapsed-container handling via a reveal event.
- Run-record telemetry: the runner auto-reports to `POST /runs`, sent as `text/plain` beacons because JSON beacons drop silently cross-origin.
- A safety posture written into the code, not just the spec: auto-mode against external sites is hard-disabled, and `type` values on external surfaces must be `{{inputs.*}}` templates so no literal secret can be persisted in a script.

## Contracts other modules depend on
- **Schema identifier:** `interact.v1` (`SCHEMA_VERSION`). A script whose `schema` field differs is rejected.
- **Script ids:** `<feeder-namespace>:<slug>`, matching `^[a-z0-9][a-z0-9-]*:[a-z0-9][a-z0-9-]*$`. Namespaces have registered owners (`NAMESPACE_OWNERS`; `chat:` → product-awareness, `payor:` → payor registry).
- **HTTP surface:** `GET /health`, `POST /validate`, `POST /scripts`, `GET /scripts`, `GET /scripts/{script_id}`, `GET /scripts/{namespace}/{slug}`, `DELETE /scripts/{script_id}`, `POST /runs`, `GET /runs`, plus `GET /runner.js` and `GET /demo`.
- **Response headers:** `X-Interact-Version`, `X-Interact-Published-By` (CORS-exposed); `?meta=1` returns the same as an envelope.
- **Provenance header on write:** `X-Feeder-Source`, echoed back as `published_by`.
- **Tables:** `interact_scripts` (id, schema, script JSONB, updated_at, version, published_by) and `interact_runs` (run_id, script_id, mode, surface, started_at, finished_at, outcome, steps JSONB, correlation_id, duration_ms, abort_reason).
- **Anchor convention:** on Mobius-owned surfaces, steps must target `[data-tour-id=...]`; CSS and `text:` selectors fail validation there. This makes `data-tour-id` attributes in other modules' markup a cross-module contract.
- **Golden fixtures:** `fixtures/` holds the two spec scripts (guide + RPA). Breaking either is defined as a schema break requiring a version bump.

## Known gaps carried into v1.0.0
- Write auth is unenforced. `POST /scripts` and `DELETE /scripts/{id}` trust `X-Feeder-Source` as provenance only — any caller can write or delete any namespace. The design doc records a real clobber incident on 2026-07-08 (a smoke test overwrote production `chat:upload-a-document` v3) that was caught only because the author was watching.
- Auto mode against external sites is hard-disabled. `INTERACT_ENABLE_EXTERNAL_AUTO` exists as a flag; enabling it requires an allowlist and explicit policy sign-off that do not exist yet. The external driver (P4) is unbuilt.
- Text-match selectors (`text:` prefix) are supported as a last-resort tier for external sites and are locale-fragile by construction.
- Reads are deliberately open and anonymous (CORS) because the chat chip depends on it; there is no rate limiting or per-caller accounting on the read surface.
