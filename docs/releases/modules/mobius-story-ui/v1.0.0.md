## What this module is
A standalone FastAPI server that hosts the Mobius narrative deck and its companion pages for the Florida Medicaid behavioral-health market. It serves static HTML (`story.html` and siblings) and proxies two upstream APIs — mobius-chat and the skills API — so the deck can hold live chat and pull real data without CORS problems. It is a presentation and demo surface, not a data owner.

## What v1.0.0 establishes
- A FastAPI static-file server (`server/main.py`) with `/health`, a root redirect to `/story.html`, and a `public/` mount.
- A transparent proxy layer: `/proxy/chat/{path}` to mobius-chat and `/proxy/skills/{path}` to the skills API, with hop-by-hop headers stripped and true SSE streaming for `/chat/stream/*` so tokens render as they arrive.
- Graceful degradation when the skills API is unavailable — fail-fast 503, cleared spinners, static BHPF baseline data, and "BHPF aggregate" fallback narrative instead of error text.
- The full narrative deck: an eight-beat executive summary written for a BHPF CEO audience, Acts I–VIII, and a value-claim spine where every figure is anchored to the Act IV four-bucket gap.
- A per-slide module architecture: `SLIDE_MODULE_SPEC.md` defines slide identity, live/static/hybrid data blocks and per-slide chat context; 34 entries now live under `public/slides/` including `_template` and `_shared`, with a `build_act2.py` build step.
- Static data mode: pre-baked snapshot JSON under `public/data/` (admin benchmarks, panel/retention/code series, cover statics) so the deck renders fully with no backend.
- Slide-level chat driven by per-slide `system_prompt.md`, with MCP data-tool responses rendered as `ui_blocks` tables and ranked org lists auto-rendered as bar charts.
- Deployment: Dockerfile at repo root, `deploy/cloudbuild.yaml`, `scripts/deploy.sh`, and Cloud Run wiring for the skills service.

## Contracts other modules depend on
- **HTTP surface**: `GET /health` (returns `service` and the configured `chat_api`), `GET /` redirecting to `/story.html`, `/proxy/chat/{path}` and `/proxy/skills/{path}` (GET, POST, PATCH, DELETE, OPTIONS), and the `public/` static mount serving `story.html`, `org.html`, `roster.html`, `run.html`, `report.html`, `progress.html`, `upload.html`, `displacement.html`, `acts_preview.html`, `mobius-demo-mockup.html`.
- **Upstream contracts consumed**: mobius-chat `POST /chat`, `GET /chat/response/*`, and `/chat/stream/*` (SSE), with `chat_mode` restricted to `agentic|copilot|quick`; the skills API path space is forwarded verbatim.
- **Configuration**: `UI_PORT` (default 8020), `CHAT_API_URL` (defaults to the deployed mobius-chat dev service), `SKILLS_API_URL` (default `http://localhost:8011`).
- **Slide module contract**: `SLIDE_MODULE_SPEC.md` — `manifest.json` per slide with `id`, `slug`, `act`, `sequence`, `chapter`, `tags`, and `blocks[]` carrying `data_mode` (`live` | `static` | `hybrid`), `static_source`, `live_source`, `endpoint`, `chat_context`.
- **Static data files**: the JSON snapshots in `public/data/` are read directly by the deck; renaming or reshaping them breaks slides.

## Known gaps carried into v1.0.0
- The refactor is incomplete: `story.html` remains a monolith holding the Acts VI–VIII slides, while 34 module directories exist under `public/slides/` — two authoring paths coexist.
- CORS is `allow_origins=["*"]` with all methods and headers, and both proxies forward client headers largely intact; there is no authorization at the proxy.
- The sign-in flow needed a loop-breaker and a visibility guard as recent fixes, which indicates the auth bounce is fragile rather than settled.
- Static snapshot JSON is baked at survey/build time with no freshness marker in the served page, so a stale snapshot and a live figure look identical to a viewer.
- The skills-unavailable path is detected partly by string-matching the configured URL (`not-yet-deployed`, `invalid`) rather than by a health check.
