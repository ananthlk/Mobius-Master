# mobius-qa v1.0.0

**Commit:** `7fe4ae2` · **Branch:** `main` · **History:** 71 commits, 2026-03-13 → 2026-08-04

## What this module is
mobius-qa holds Mobius's evaluation and corpus-hygiene tooling: the chat eval bot that scores the product end to end, a retrieval-only bake-off harness, an eval studio for authoring and running suites, and the lexicon-maintenance service that triages and curates lexicon candidates. It grades other modules; it is not part of any request path they serve.

## What v1.0.0 establishes
- **mobius-chat-qa** — a five-vector eval runner (`run_eval.py`) that drives `POST /chat` over SSE with an optional HTTP poll, scores rubric vectors A–E via an LLM adjudicator, writes markdown reports, and persists to PostgreSQL `eval_runs` / `eval_results`.
- **retrieval-eval** — a retrieval-only harness comparing `hier_only` against `atomic_plus_hier` on the same question set against the dev Vertex index, emitting `results.csv`/`results.jsonl`, `summary.md`, and similarity/confidence distribution plots.
- **retrieval-eval-studio** — a FastAPI service (~1,800 lines) for suite lifecycle: create suites, edit specs, import questions from YAML, auto-generate questions, list documents, launch runs, and read per-run and per-question results.
- **lexicon-maintenance** — a deployed FastAPI + React service that turns raw candidate phrases into a curated lexicon: a rule-named triage pipeline with an LLM confidence gate, a durable decision catalog, a collapse/purge analyzer for sub-phrase duplicates, health analysis with preview/apply fixes, publish, and push-to-chat.
- A background drain path for the candidate backlog — band-parallel, hash-partitioned workers with bounded bursts, monotonic counters, and force-restart on a stale heartbeat, built specifically to survive the 60s request timeout.
- Production hardening of lexicon-maintenance: admin-key auth, then HttpOnly-cookie session login, then acceptance of the mobius-os platform JWT so it reuses central auth rather than its own key; DB timeouts, targeted indexes, and a Dockerfile with a Cloud Run dev deploy script.
- Grading integrity as an explicit property: continuous per-producer-stage quality scores from the v2 adjudication writer, with grader self-grading removed and the judge model recorded as provenance.

- **Auth** — lexicon-maintenance accepts the mobius-os platform JWT; a change to that token's issuance breaks this service's login.

## Known gaps carried into v1.0.0
- The drain batch size of 35 is an empirically reverted value, not a calibrated one — 90 was tried and produced mass skips, and no model-side cause was established.
- Disposition is served from a cache because the live aggregate exceeds the 60s timeout on the current SQL tier, so the funnel a reviewer sees can be stale.
- Two frontends exist for lexicon-maintenance (`frontend/` and `frontend-v2/`) with no stated deprecation of the older one.
- `retrieval-eval` targets the dev Vertex Vector Search index and requires a manually ingested, chunked, embedded, published, and synced corpus; it does not verify that precondition and will silently evaluate whatever is in the index.
- `quality_ruler` is NULL for heuristic-only adjudications, so the authoritative `quality_ruler='gemini-2.5-pro'` filter excludes those rows — the excluded fraction is not reported anywhere in this repo.
- Only lexicon-maintenance has a test directory and `run_tests.sh`; mobius-chat-qa, retrieval-eval, and retrieval-eval-studio ship without tests of their own.
