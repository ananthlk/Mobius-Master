# mobius-chat v1.0.0

**Commit:** `3fa105d` · **Branch:** `main` · **History:** 1062 commits, 2026-01-31 → 2026-09-07

## What this module is

mobius-chat is the conversational front door to Mobius. A question enters over HTTP, is
published to a queue (memory or Redis backend), and a background worker runs it through a
planner and a ReAct loop that calls tools — corpus retrieval, service-line registry lookups,
appeals tools, document readers, NPI lookup — before publishing a rendered answer back by
correlation id. It also hosts the operator surfaces: prompt-composition admin, org/employee
setup, credentialing runs, and the platform view.

## What v1.0.0 establishes

- A queue-decoupled request/response architecture (`publish_request` → worker →
  `publish_response` → `get_response(correlation_id)`) with a pluggable memory or Redis backend,
  so API and worker can run as separate processes.
- A ReAct answering loop (`app/pipeline/react_loop.py`) driven by a declared tool manifest
  (`app/pipeline/tool_manifest.py`) rather than free-form model choice, with a completion-gate
  critic, groundedness critic, wall-clock guards and retrieval-budget math.
- A tool surface spanning corpus search, uploaded-document search, service-line registry
  lookups, appeals tools, healthcare/NPI lookup, URL ingest and web scrape — each an explicit
  manifest entry with allow-lists per mode.
- A rendered-answer contract: deterministic markdown/table formatting, citation footnotes, a
  certified-answer block for service-line facts, and a structured disambiguation block that
  resubmits a selection straight back into the tool call.
- Diagnostics as a first-class product: per-call RAG round rendering, web-scrape provenance
  panels (pages visited, robots decisions), and correlation-id-scoped feedback, QC and
  adjudication endpoints.
- Operator surfaces: prompt blocks/compositions/versions admin, model registry and model-health
  degradation, org setup and datastore provisioning, credentialing-run management.

## Known gaps carried into v1.0.0

- Structured output is Vertex-only: `response_schema` is handed to Vertex and withheld from
  other providers, so schema-constrained generation is not uniform across the model registry.
- Recent-chats sidebar has a known `thread_id` / `chat_threads` write-path defect tracked as
  coordination item #108; it is recorded, not closed.
- The service-line answer path required a run of same-week corrections (verbatim quoting,
  caveat-vs-directive separation, HCPCS competence-claim exclusions). The manifest overrides that
  keep it correct are hand-placed, not derived.
- Model-health degradation distinguishes permanent from transient failures by error
  classification; the thresholds behind that classification are not calibrated against a
  measured failure distribution.
- The 90s turn deadline is defended by wall-clock guards and fail-fast RAG calls added
  reactively; there is no global budget accounting that prevents a new tool from re-introducing
  the stacking problem.
