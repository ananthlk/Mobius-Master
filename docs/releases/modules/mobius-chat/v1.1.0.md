# mobius-chat v1.1.0

**Commit:** `385d5a1` · **Branch:** `main` · **Since v1.0.0:** 8 commits, 2026-09-07

## Why this is a MINOR

New capability, no contract broken. Everything added is additive: one new API
route, one new tab, and a widened lookup path in an existing route. No caller of
chat changes, no response shape changes, and nothing another module reads was
altered.

## What changed

- **The platform page became the framework surface.** Modules are grouped by the
  7+1 layer model, each showing what it RUNS, which repo holds the CODE, and its
  OWNER. Fed from `platform-definition.json`, so the grouping is data rather than
  markup.
- **A Releases tab**, served from `/api/platform/releases`, which reads the
  generated `docs/releases/product-*.lock.json` files. It cannot drift from what
  was tagged because it does not restate it — and it earned that immediately,
  rendering 29 excluded files where the hand-written v1.0.0 story claimed 30.
- **The framework was rebuilt from the code**, not from the roster of Claude
  agent seats it had been describing. Modules are deployed services and in-repo
  code modules traced to the config that names them; seats moved to an `owner`
  field. Four services no config names are labelled unverified rather than
  asserted.
- **Skills are classified by invocation, not deployment.** A skill that happens
  to be its own Cloud Run service is still a skill; only queue-driven work is a
  worker. Pre-Layer 0 renders as the six-stage ingestion pipeline and references
  components in whatever layer they live in.
- **The docs the page reads now ship in the image.** `docs/` was never copied, so
  every `/docs/` link had been 404 in dev while working locally, and
  `/api/platform/definition` had been silently falling back to GitHub.

## New or changed contracts

- `GET /api/platform/releases` — new. Returns `{releases: [...], current: "product-vX.Y.Z"}`
  read from the release lockfiles.
- `GET /docs/{filename}` — widened. Now resolves a document by basename across
  `docs/`, `docs/releases/` and `docs/releases/modules/*`. Lookup stays
  server-controlled; the caller cannot supply a path.
- Image now contains `/docs` (~240 KB: release manifests, the two architecture
  documents, the diagram, `platform-definition.json`).

## Known gaps carried forward

- The `thread_id` write-path bug (#108) from v1.0.0 is unchanged.
- Structured output remains Vertex-only.
- Three platform modules are marked `unverified` because no deploy config names
  their service; the page says so rather than guessing.
