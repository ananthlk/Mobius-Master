🔴 The measured gap. phi_classify runs 1,867 times / 30d at 0% correlation_id coverage — and the code comment says why: “all 98 phi_classify llm_calls rows/day landed with correlation_id NULL and attributed to no turn.” So a gate that runs inside the promise window, on the user''s request path, cannot be attributed to the turn it gated. Its cost is $0.10/30d — trivial — but its latency is inside the promise and its verdict is a compliance record, and neither joins to a turn.
Why PHI is a lane and not a stage. It gates before the promise clock has anything to measure, instructs inside every prompt as an authority block, audits to its own append-only table, and now persists into a new table 067 introduces. A stage can be skipped by a tier; this cannot. `fast` skips NARROW and VALIDATE — nothing skips the PHI gate, and the schematic has to show that or it invites exactly that mistake.

8 · COMMUNICATE — ONE exit, selected components NEW

module app/pipeline/v2/communicate.py  ·  owner Governor (selection) · LLM Agent (blocks) · Chat seat (renderers)
🔴 THE HARD CONSTRAINT — Ananth: “there should just be ONE way to communicate out, even on early exit. I have had too much trouble with that.”

Exactly one function emits to the user. Every path reaches it — success, early exit, budget exhaustion, capability, error. No exceptions, no bypass.

This is the fix for the measured mess: 8 publish call sites across 2 reachable terminals, 1 terminal with zero callers that survived a 2,181-line refactor, an early return on empty payload at :1385, and two early exits (:6116 golden-answer, :6134 fast-mode) that each leave by their own door. An early exit is not a different path — it is an exit_mode passed into the one path.

Correction to my own §11 formula. I wrote use_enricher ⇔ rounds>1 OR tools>1 — one boolean over the whole stage. Wrong: diagnostics can never be skipped, so there is a floor the enricher''s 5.2s figure was never the right unit for. The decision is per component, and for the card it is which of three writers, not whether to write.

The failure this constraint prevents is structural, not behavioural: today the paths that most need to say something are exactly the ones that leave by a door where nothing says it.

The uniform contract, and the rule under it. estimate(inputs) → {latency_ms, cost_c, confidence} · run(inputs, directive) pure, clock is an input · AFFECTS signed per term · PRECONDITIONS. A module the governor cannot price cannot be budgeted — “is one more round worth it?” is unanswerable if a component’s cost is learned only by paying it.

Conformance — the formulas that grade it

kept        ⇔ delivered ≤ promised
in_band     ⇔ delivered ≤ promised + band          three outcomes, not a boolean
queue_wait  = delivered_latency_s − worker_latency_s  derived, never stored

v2 phase advances ⇔ over ≥200 turns, ALL of:
    in_band(v2) ≥ in_band(v1)          same tier, same window
    no new breach class
    turns == rows  AND  dupes == 0  AND  queue_wait ≥ 0 on every row
    CAPABILITY_rate(v2) ≤ CAPABILITY_rate(v1)      ← v2 stopped reaching tools
    gaps_closed_per_turn(v2) ≥ v1                   ← fewer answers for better latency
    unknown_outcomes == 0
Why those last two are the gate and the rest is the dashboard. Every other metric improves when v2 does less. Latency, cost and conformance all move the right way if v2 quietly stops reaching tools. Only those two move the wrong way — which is what makes them the real test.

What the two clocks measure

posted_at ────────────────────────────────────────────── published_at
   │            │                                    │
   │  queue     │  worker: t0_start ─── duration_ms ─┘
   │  wait      │
   └── accept ──┘        delivered_latency_s = published_at − posted_at   ← THE PROMISE
                         worker_latency_s    = duration_ms                ← the old number
                         queue_wait          = delivered − worker         ← derived, never stored
Three things must hold on every row. queue_wait ≥ 0 — a negative means the two clocks were mixed and the wiring is wrong. turns == rows — the finally fired exactly once. And delivered_cost_c is null, never 0.0 — a zero is a step-1 failure, not a cheap turn.
